Authentication
Use Case 1: Authentication
Use Case Goal: To allow authorized users to securely access the Logistics Management System with Client Feedback Mechanism based on their assigned role.
Scenario 1: Successful login and access to dashboard.
Actor: Owner / Warehouse Staff / Driver / Client
Pre-condition: The system is running and accessible. The user has an active registered account. For Client, the account must already be verified through OTP/email confirmation.
Main Flow:Step 1: The user enters a registered email/username and password.Step 2: The system validates the entered credentials against the user records in the database.Step 3: The user clicks the Login button.Step 4: The system authenticates the user and determines the assigned role.Step 5: The system redirects the user to the appropriate dashboard or interface based on role.
User Action: Enters email/username and password.System Response: Validates the provided credentials.
User Action: Clicks “Login.”System Response: Confirms that the credentials are correct, verifies the user role and account status, creates a user session, and redirects the user to the assigned dashboard or interface.
Scenario 2: Client registration and OTP/email confirmation.
Actor: Client
Pre-condition: The system is running and accessible. The Client does not have an existing account.
Main Flow:Step 1: The Client opens the registration page.Step 2: The Client enters the required registration details.Step 3: The system validates the registration details.Step 4: The system creates a new Client account record.Step 5: The system sends an OTP/email confirmation code to the Client.Step 6: The Client enters the OTP/email confirmation response.Step 7: The system verifies the OTP/email confirmation response and updates the Client account status as verified.
User Action: Enters Client registration details.System Response: Validates the registration details and creates a new Client account record.
User Action: Enters the OTP/email confirmation response.System Response: Confirms the OTP/email verification and activates the Client account.
Scenario 3: Owner manages staff and driver credentials.
Actor: Owner
Pre-condition: The Owner is logged in and has access to staff and driver credential management.
Main Flow:Step 1: The Owner opens the staff and driver credential management page.Step 2: The Owner enters new staff or driver account details or updates existing credentials.Step 3: The system validates the staff or driver credential details.Step 4: The system saves the new staff or driver account record or updates the existing credentials.Step 5: The system displays a credential management confirmation.
User Action: Enters or updates staff/driver credential details.System Response: Validates the credential details.
User Action: Saves the staff/driver credential details.System Response: Stores the new or updated staff/driver credentials and displays a confirmation message.
Scenario 4: Change or reset password.
Actor: Client / Owner
Pre-condition: The Client has an existing account, or the Owner is logged in and managing a staff or driver account.
Main Flow:Step 1: The Client requests a password reset, or the Owner selects a staff/driver account for password change.Step 2: For Client , the system sends an OTP/email password reset code.Step 3: The Client enters the OTP/email password reset response, or the Owner enters the new staff/driver password.Step 4: The system validates the password reset or password change request.Step 5: The system updates the password record in the database.Step 6: The system displays a password update confirmation.
User Action: Requests password reset or enters a new password for the selected account.System Response: Validates the password change request.
User Action: Submits the password reset or password change.System Response: Updates the password record and displays a password update confirmation.

Inventory Management
Use Case 4: Inventory Management
Use Case Goal: To allow the Owner and Warehouse Staff to receive stock batches, categorize stock, update inventory records, record inventory transactions, and monitor stock availability.
Scenario 1: Receive and categorize stock batch.
Actor: Warehouse Staff
Pre-condition: The system is running and accessible. The Warehouse Staff is logged in and has access to inventory management. Product records already exist in the system.
Main Flow:Step 1: The Warehouse Staff opens the inventory management module.Step 2: The system displays the inventory management options.Step 3: The Warehouse Staff enters the received stock batch details.Step 4: The system saves the new stock batch record.Step 5: The Warehouse Staff categorizes the stock based on variety, unit size, assorted size, and quantity per case/category.Step 6: The system updates the stock batch classification details.Step 7: The system displays a stock batch confirmation.
User Action: Opens the inventory management module.System Response: Displays the inventory management options.
User Action: Enters received stock batch details.System Response: Saves the new stock batch record.
User Action: Categorizes the stock batch.System Response: Updates the stock batch classification details and displays a stock batch confirmation.
Scenario 2: Update inventory quantity.
Actor: Warehouse Staff
Pre-condition: The system is running and accessible. A categorized stock batch record is available.
Main Flow:Step 1: The Warehouse Staff selects the categorized stock batch for inventory update.Step 2: The system retrieves the categorized stock batch details.Step 3: The system validates the stock batch quantity.
Step 4: The system updates the inventory quantity.Step 5: The system saves the updated inventory record.Step 6: The system prepares the stock movement details for inventory transaction recording.Step 7: The system displays an inventory update confirmation.
User Action: Selects the categorized stock batch for inventory update.System Response: Retrieves and validates the categorized stock batch details.
User Action: Confirms the inventory update.System Response: Updates the inventory quantity and saves the updated inventory record.
User Action: Completes the inventory update process.System Response: Prepares the stock movement details and displays an inventory update confirmation.
Scenario 3: Record inventory transaction.
Actor: Warehouse Staff
Pre-condition: The system is running and accessible. An inventory update has been made and stock movement details are available.
Main Flow:Step 1: The Warehouse Staff opens the inventory transaction section.Step 2: The system displays the stock movement details.Step 3: The Warehouse Staff confirms the stock movement type.Step 4: The system identifies whether the movement is stock in, stock out, or adjustment.Step 5: The system records the inventory transaction.Step 6: The system saves the inventory transaction record.Step 7: The system displays an inventory transaction confirmation.
User Action: Opens the inventory transaction section.System Response: Displays the stock movement details.
User Action: Confirms the stock movement type.System Response: Identifies the movement as stock in, stock out, or adjustment.
User Action: Saves the transaction.System Response: Records and saves the inventory transaction, then displays an inventory transaction confirmation.
Scenario 4: Monitor stock availability.
Actor: Owner / Warehouse Staff
Pre-condition: The system is running and accessible. Inventory records and inventory transaction records are available.
Main Flow:Step 1: The Owner or Warehouse Staff opens the stock monitoring section.Step 2: The system retrieves the updated inventory records.Step 3: The system retrieves the stock movement records.Step 4: The system checks current stock levels.
Step 5: The system displays stock availability status.
Step 6: The system displays stock movement summary.Step 7: The system displays low stock notification if any item reaches the low stock level.
User Action: Opens the stock monitoring section.System Response: Retrieves updated inventory records and stock movement records.
User Action: Views the stock monitoring page.
System Response: Displays stock availability status and stock movement summary.
User Action: Reviews stock alerts.System Response: Displays low stock notification if applicable.
